# Описание проекта

Проект решает задачу **бинарной классификации**: по клиническим показателям пациента
(возраст, пол, давление, холестерин, результаты ЭКГ и нагрузочных проб) определить
значение целевой переменной `target`.

Исходная выборка: [Heart Disease Dataset](https://www.kaggle.com/datasets/krishujeniya/heart-diseae)
(Cleveland Heart Disease, репозиторий UCI) — 303 записи, 13 признаков.

# Запуск

Для запуска проекта под ОС GNU/Linux необходимо выполнить команды:

```shell
git clone https://github.com/0legzuz/iis_oleg.git
cd iis_oleg
python3 -m venv .venv_heart
source .venv_heart/bin/activate
python3 -m pip install -r requirements.txt
```

Активация виртуального окружения:

```shell
source .venv_heart/bin/activate
```

Деактивация:

```shell
deactivate
```

Запуск Jupyter для работы с блокнотом:

```shell
jupyter notebook eda/eda.ipynb
```

### Данные

Файлы с данными в репозиторий не коммитятся. Перед запуском блокнота нужно скачать
датасет и положить его в директорию `./data/` под именем `heart.csv`:

```shell
mkdir -p data
curl -o data/heart.csv https://raw.githubusercontent.com/kb22/Heart-Disease-Prediction/master/dataset.csv
```

> Для пересохранения интерактивного графика в PNG библиотеке `kaleido` нужен браузер
> на движке Chromium. Если он не установлен, выполните `plotly_get_chrome`.
> Сам блокнот при этом читается и без него — графики уже сохранены в `./eda/`.

# Запуск MLflow

Эксперименты по настройке модели логируются в MLflow. Сервер поднимается локально,
хранилище экспериментов и реестр моделей — в СУБД sqlite.

Скрипт запуска лежит в `./mlflow/start_mlflow.sh`. Запускать **из каталога `mlflow`**:

```shell
cd mlflow
sh start_mlflow.sh
```

После запуска интерфейс доступен по адресу http://localhost:5000

Рядом со скриптом появятся база `mlruns.db` и каталог `mlartifacts` с сохранёнными
моделями — в репозиторий они не коммитятся.

Блокнот с экспериментами — `./research/research.ipynb`. Сервер MLflow должен быть
запущен **до** выполнения блокнота.

# Исследование данных

Находится в `./eda/eda.ipynb`.

## Действия на этапе очистки данных

* Удалена 1 полностью дублирующаяся запись
* Удалены 4 записи со значением `ca = 4` и 2 записи со значением `thal = 0` — эти значения
  выходят за границы кодировки признаков (`ca` кодируется 0–3, `thal` — 1–3) и являются
  замаскированными пропусками исходного датасета UCI. Всего строк с `ca = 4` было пять,
  но одна из них совпала с дубликатом. Итого удалено 6 записей из 303,
  **итоговый размер выборки — 296 строк**
* Проверены диапазоны всех числовых признаков (`age`, `trestbps`, `chol`, `thalach`,
  `oldpeak`) — значения физиологически правдоподобны, невалидных нет
* Пропущенных значений (`NaN`) в датасете нет, восстанавливать ничего не потребовалось
* Понижена разрядность типов: категориальные признаки и `target` приведены к `int8`,
  `trestbps`, `chol`, `thalach` — к `int16`, `oldpeak` — к `float32`

## Созданные признаки

* `age_group` — возрастная группа, биннинг признака `age` по десятилетиям
  (29–40, 41–50, 51–60, 61–70, 71–80). Используется для сравнения долей классов
  между возрастными когортами

## Выявленные закономерности

* Наиболее информативные признаки по корреляции с целевой переменной: `ca` (−0.47),
  `oldpeak` (−0.43), `thalach` (+0.43), `exang` (−0.43), `cp` (+0.42)
  (см. [график](./eda/correlation.png))
* `thalach` (максимальный пульс) разделяет классы лучше всех числовых признаков:
  медиана 161 уд/мин у класса 1 против 141 у класса 0
  (см. [интерактивный график](./eda/numeric_boxplot.html), [png](./eda/numeric_boxplot.png))
* `oldpeak` у класса 1 в подавляющем большинстве случаев равен нулю — признак работает
  почти как бинарный индикатор (см. [график](./eda/numeric_by_target.png))
* `ca` даёт строго монотонную зависимость: доля класса 1 падает с 0.75 при `ca = 0`
  до 0.15 при `ca = 3` (см. [график](./eda/categorical_by_target.png))
* `thal = 2` даёт долю класса 1 равную 0.78 против 0.33 и 0.23 у значений 1 и 3
  (см. [график](./eda/categorical_by_target.png))
* Пол — самостоятельный фактор, а не следствие разницы в возрасте: доля класса 1
  у женщин выше мужской в **каждой** возрастной группе
  (см. [график](./eda/risk_by_age_sex.png))
* Разделяющая способность `thalach` зависит от возраста: у класса 1 пульс падает
  на 1.05 уд/мин в год, у класса 0 — лишь на 0.37, поэтому линии тренда сходятся.
  Разрыв между классами составляет 27 уд/мин в 40 лет, 13 в 60 и практически исчезает
  к 70 (6 уд/мин). Признак хорошо работает только для пациентов до 60 лет, а модели
  стоит явно подать взаимодействие `age × thalach` (см. [график](./eda/thalach_vs_age.png))
* Стенокардия при нагрузке связана с низким пульсом: средний `thalach` при `exang = 1`
  равен 137 уд/мин против 156 при `exang = 0` (см. [график](./eda/thalach_vs_age.png))
* Кандидаты на исключение при отборе признаков — `fbs` (корреляция с целевой
  переменной −0.005) и `chol` (−0.08)
* `slope` и `oldpeak` частично дублируют друг друга (взаимная корреляция −0.58),
  оба описывают поведение сегмента ST — разумно оставить один из них
* Мультиколлинеарности между остальными признаками нет: все прочие попарные
  корреляции по модулю не превышают 0.40
* Числовые признаки различаются по масштабу на два порядка, поэтому в пайплайне
  модели обязательна нормировка (`StandardScaler`)
* Классы сбалансированы (160 против 136 после очистки) — балансировка выборки
  не потребуется

## Замечание о разметке целевой переменной

Источник описывает `target = 1` как наличие заболевания, однако все выявленные связи
указывают на обратное: класс 1 — это высокий максимальный пульс, нулевая депрессия ST,
отсутствие стенокардии при нагрузке и `ca = 0`, то есть набор **благоприятных**
клинических показателей. Такая инверсия меток известна для публикаций этого датасета.

На обучение модели это не влияет, но при интерпретации предсказаний в сервисе
порядок меток нужно перепроверить.

Обработанная выборка сохранена в файл `./data/clean_data.pkl`.

# Результаты исследования

Эксперименты проведены в `./research/research.ipynb`, все прогоны залогированы в MLflow
(эксперимент `Heart Disease Classification`).

## Сравнение экспериментов

Выборка разбита на обучающую и тестовую в пропорции 75/25 со стратификацией по классу.
Метрики посчитаны на тестовой части.

| Конфигурация | precision | recall | f1 | roc_auc |
|---|---|---|---|---|
| baseline | 0.7619 | 0.8000 | 0.7805 | 0.8518 |
| feature_engineering | 0.7111 | 0.8000 | 0.7529 | 0.8349 |
| feature_selection | 0.7500 | 0.8250 | 0.7857 | 0.8364 |
| **optuna_tuned** | **0.7727** | **0.8500** | **0.8095** | **0.8412** |

Основная метрика для сравнения — `f1`: классы близки к сбалансированным, и она учитывает
и точность, и полноту.

## Лучшая модель

Лучший результат показала модель **`optuna_tuned`** — случайный лес с подобранными
гиперпараметрами, обученный на отобранных признаках: **f1 = 0.8095**, roc_auc = 0.8412.

Путь к этому результату:

1. Генерация признаков (`PolynomialFeatures` для `age`, `thalach`, `oldpeak` и
   `KBinsDiscretizer` для `trestbps`, `chol`) расширила набор с 13 до 24 признаков,
   но **качество ухудшила** — f1 упал с 0.7805 до 0.7529. На выборке в 296 записей
   лишние признаки вносят шум.
2. Отбор 12 признаков из 24 методом `SequentialFeatureSelector` (mlxtend, forward)
   вернул качество и превзошёл baseline: f1 = 0.7857.
3. Подбор гиперпараметров `optuna` на этой конфигурации (15 испытаний, максимизация f1
   по кросс-валидации) дал итоговые f1 = 0.8095.

### Параметры лучшей модели

```
n_estimators = 114
max_depth    = 10
max_features = 0.7412
```

### Отобранные признаки (12 из 24)

```
numeric__trestbps        categorical__ca
numeric__chol            categorical__thal
numeric__oldpeak         poly__age oldpeak
categorical__cp          poly__thalach oldpeak
categorical__exang       poly__oldpeak^2
categorical__slope       kbins__chol
```

Индексы: `1,2,4,6,9,10,11,12,18,20,21,23`

Для сравнения тот же отбор выполнен методом `RFE` (движется в обратную сторону —
удаляет наименее важные). Алгоритмы совпали на **8 признаках из 12 (67%)**; оба
уверенно выбрали `cp`, `ca`, `thal`, `slope`, `chol` и полиномиальные комбинации
с `oldpeak`.

## Production-модель

Финальная модель обучена на **всей** выборке (296 записей, 13 исходных столбцов)
и зарегистрирована в реестре `heart-disease-rf` как **версия 3** с тегом `Production`.

```
run_id = 857216a4e3f345b8bb9b53c7c8d61a57
```

Обращаться к ней можно по алиасу: `models:/heart-disease-rf@Production`

Используемые столбцы: `age`, `sex`, `cp`, `trestbps`, `chol`, `fbs`, `restecg`,
`thalach`, `exang`, `oldpeak`, `slope`, `ca`, `thal` (см. `research/production_columns.txt`).

Скриншоты интерфейса MLflow и файл описания модели:
[прогоны с метриками](./research/model_runs.png),
[версии модели](./research/model_versions.png),
[MLmodel](./research/MLmodel).

> **О версиях библиотек.** В методичке указаны `mlflow==2.16` и `numpy==1.26.4`.
> Здесь используется `mlflow==3.16.1` с актуальным `numpy==2.5.3`: откат numpy
> до 1.26.4 сломал бы блокнот ЛР1, который работает на `pandas==3.0.5`.
> Совместимость проверена — оба блокнота выполняются в одном окружении без ошибок.
